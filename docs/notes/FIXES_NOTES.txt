     -> handlers read _current_ctx set from indexAt(pos); refresh() re-applies

     Quality combo in AddDownloadDialog (background-thread probe + Signal).

SESSION B — RECORDING CORRUPTION FIX:
  1. Upload bypasses chrome.runtime.sendMessage (~32MB cap truncated long
     takes). New nonce flow: background.js GET_UPLOAD_NONCE -> token-gated
     POST /upload-token -> content.js POSTs the blob DIRECTLY to /upload
     with a one-time X-Upload-Nonce header. Nonces: 128-bit, 5-min expiry,
     single use. Old UPLOAD_RECORDING handler removed.
     DEVIATION from handoff: CORS for /upload widened to any origin —
     content-script fetches carry the PAGE origin, not the extension's, so
     the original CORS config would have blocked every upload. Safe because
     /upload still requires the unforgeable nonce.
     SECOND DEVIATION (per DeepSeek's own verification item #4): content.js
     falls back to <a download> ONLY on nonce/network failure. A server
     rejection (corrupt recording) shows the error on the pill instead.
  2. _repair_recording(): ffmpeg remux with -fflags +genpts after save;
     original only replaced when the remux output verifies.
  3. _probe_recording(): ffprobe duration check before the job is marked
     done; corrupt uploads become error-status jobs and return HTTP 400.
     build-exe.yml / build_exe.md now bundle ffprobe.exe too.
  4. Upload/validated sizes logged.
  TEST: record ~2min blob video; log should show
  "recording upload (N bytes)" -> "recording repaired" ->
  "recording validated (M bytes)" -> "converted ... .mp4"; file plays in WMP.

SESSION F — DEEPSEEK SECOND-REVIEW PASS (6 items, all closed):
  1. content.js MSE-branch menu: `mse || isExtractorSite()` collapsed to
     `isExtractorSite()` — in that branch mse is always true, so "Send page
     URL to yt-dlp" appeared on every MSE site incl. ones with no yt-dlp
     extractor (guaranteed-failure menu item). Twitch unaffected (it's in
     EXTRACTOR_HOSTS).
  2. server.py /upload dispatch race (HIGH): new_job() gained defer=False;
     defer=True creates the job as status "held", invisible to the 1 Hz
     dispatcher_loop (which picks up only status == "queued"). /upload now
     passes defer=True, so the repair/ffprobe window can no longer spawn a
     bogus generic download against upload:/// URLs. /upload already flips
     status to done/error directly afterward.
  3. background.js interception HEAD probe: fetch(..., {method:"HEAD"})
     -> added credentials:"include" (service-worker fetches omit cookies by
     default; authenticated downloads silently failed the attachment gate).
  4. content.js probeFormatsCached: FORMAT_CACHE no longer caches failures
     — entry deleted on lastError / null resp / resp.ok === false; next menu
     open re-probes.
  5. popup.js grab-all path: resp.job_ids.length -> (resp.job_ids || []).length
     (sendBatch already guarded; grab-all path threw TypeError on failure).
  6. options.js Test connection: new GET /ping endpoint (returns
     {ok, paired, token-if-paired}, never flips _PAIR_GRANTED; CORS already
     covers chrome-extension://* on all routes). Button now pings first:
     reachable+paired -> "already paired this session" (ok); reachable+
     unpaired -> POST /pair as before; unreachable -> clear "is the app

  Housekeeping: manifest.json version 1.0.0 -> 3.2.0 (matches README).
  Verified: py_compile clean; node --check clean on all 4 extension scripts;

SESSION F AUDIT (pre-download bug check) — two seams patched:
  - Crash edge: a "held" upload job only exists inside the /upload request,
    but if the app died mid-repair it would reload as invisible "held"
    forever. load_jobs_snapshot() now maps "held" -> "stopped" like
    downloading/queued, so the stranded row is visible and deletable.
  - Transition edge: options.js Test connection against a pre-/ping build
    got a bare 404 and reported "App unreachable" for a healthy app. A 404
    now says "App reachable but outdated — update Video Grabber."
  Status audit: dispatcher picks up only "queued" (held invisible); all
  other status matches (!= done, Finished filter, /convert gate, history
  pruning) treat held correctly during its sub-second window. Extension has
  <all_urls> host permission, so the credentials:"include" HEAD probe is
  CORS-exempt from the service worker. /ping is not in
  TOKEN_PROTECTED_PATHS (callable token-free, as required).

SESSION G — FULL-TREE REVIEW FIXES (3 confirmed bugs + 4 hardening items):
  1. [BUG] background.js downloads.onCreated: the browser download was
     cancelled BEFORE the backend handoff, but only a network-level throw
     re-downloaded it. HTTP rejections (400 invalid URL / 401 unpaired /
     403 / 500) resolved silently -> the user's click vanished entirely.
     Now the response is inspected: any non-ok handoff re-issues the
     original browser download as fallback.
  2. [BUG] popup.js "Select all" toggled mediaItems ignoring the active
     filter/search — hidden items got swept into batch downloads. Now
     toggles visibleItems() only.
  3. [BUG] popup.js per-row Send used filename: tab.title — every file
     from a tab was named after the page title and differentiated only by
     collision counters. Now uses fileName(it.url) (the URL's real name).
  4. [HARDEN] content.js: audio-only captureStream() result had its tracks
     left running — now stopped before bailing.
  5. [HARDEN] content.js: the format menu could render off-screen at the
     viewport bottom/right on small windows. New placeMenu() flips the
     menu above the pill / hugs the right edge as needed (both display
     branches).
  6. [HARDEN] options.js: "already paired" green state now checks that a
     token is actually stored locally — a cleared-storage session gets a
     corrective message instead of a false green.
  7. [HARDEN] popup.js grab-all: results from all frames are now deduped
     by URL (iframe + parent could list the same link twice).
  8. [VERIFIED, no change] content.js webm format picks send
     target_format="webm" with format_id — maybe_convert_target() already
     short-circuits when dest suffix == target, so no double transcode.
